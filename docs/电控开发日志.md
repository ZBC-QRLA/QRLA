**日期**：2026年10月10日

**功能描述**：把系统时钟从内部 RC 切到外部 8MHz 晶振，PLL 倍频到 72MHz，并用串口实测验证。

## 4. TIM3 四路 PWM
**日期**：2026年10月11日

**功能描述**：配好 TIM3 四路 PWM，写出 `Motor_Set(id, speed)`，用串口把 7 个测试值的限幅与方向逻辑全验一遍（没有接电机）。

**开发历程**：

- **大坑：7 行 printf 一个字都不出。** 编译成功、烧录成功、串口工具开着、程序在跑 —— 就是**一个字符都没有**。我把 USART 配置和 `_write` 都看了一遍，全对。真正原因是而我的输出结尾漏了 `\r\n`。输出没塞满缓冲区所以没串口输出，这是出现问题之前AI教程所没有提的，虽然它自己的代码没错，但我自己敲的时候敲错了。补上 `\r\n`，全部出现。
- **一个当时的决定：不接电机，只做逻辑验证** ——就是怕电机/驱动板烧了。我真的很谨慎，后来证明对了：那时 `Motor_Set` 还是错的，轮子根本不能反向运作（因为AIN对应的PA6/7当时输入速度的时候，我们0speed没有调，导致BIN对应的PB12/13反向的时候还是1电位，导致此时根本转不起来，只会短暂反向）

**经验总结**：
- AI没办法一下子考虑到所有事情，用AI也不能全盘照抄，很多时候鲸鱼老师检查半天的问题，都是被我自己认真观察or反馈之后才迅速搞定的，motor_set代码的修订就是一个例子，我们仍然需要认真且独立的思考。

## 6. 焊接 + 电机首次转动
**日期**：2026年10月13日

**功能描述**：焊好 DRV8833 排针和 TT 马达引线，第一次通电让电机真的转起来 —— 指标 2。

**开发历程**：
- 这是最累人的一集，焊接不仅消耗了我好几天的时间（因为我不会，所以又慢用小心，自己买的一个刀头还第二天就氧化了！！！），然后还烫到我的手。。
- 我遇到了上文提过的电机不能反转+最后一直转不停的问题，最后让鲸鱼老师（AI）去查了电机的真值表，终于发现代码的问题（当时她还在感谢我，笑哭，虽然也不是第一次了）
**经验总结**：
- 焊完必须先量通断，**两条判据都要**：相邻脚不响（不短路）、线圈线响而对壳不响（通且不漏）。
- 「启动不起来」和「控制错了」是两回事：前者加占空比，后者要改逻辑。**先分清是哪一类。**

- **`CCR` 不等于「力度」。** 「PWM 占空比 0%」≠「这个脚没在起作用」—— CCR 只决定一个脚的高低，**电机转不转、往哪转，是两个脚一起按真值表定的**。
- 遇到「该停不停 / 该转不转」，**先把两个脚的 4 种组合列出来查真值表，再谈 CCR**。
- **`0` 是一个有物理含义的状态，必须显式写出来**：正转 / 反转 / 停，三支都要有。
- 对AI下的判断也要敢于批判，如果不是那天晚上十一点，我超困的情况下还是认真质疑了她的一吨输出，估计我测到死也不知道自己错在哪里了

## 总结

**第一，当前最大的短板是「物理连接的可靠性」，不是算法。**
前十几天（10-03 → 10-12）几乎全在写代码和看串口，一行改对了就是进步；后六天（10-13 → 10-18）每一次「不动了」的原因，几乎**都不在代码里**：杜邦线松了、USB 接触不良、电池盒没装电池、锁定款没锁定、SMD 焊盘没做应力释放、面包板电源轨中间是断的。焊完排针、引线、降压那 4 个之后我才真懂硬件有多烦人：**「能转」和「能一直转」是两件事。**

**第二，第二大的短板是「没时间」。**
从零开始学习到现在，从快十月才临时组队到现在，已经尽力了

**第三，最有效的两个方法。**
一是 **编程文件分区**真的很有效的减少了检查的时间
二是**AI工程窗口交接的设立**：让效率和重复性错误少了很多，学习也更方便了
